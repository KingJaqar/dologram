not an installed schema, deployed endpoint, or claim of working calling. Phases
1–8 have not started. The parent plan's security, state diagram and timing budgets
remain binding. Names below that do not exist yet are explicitly **new contracts**.

## Wire contract

UTF-8 JSON, POST only, inert OPTIONS, 8,192-byte body cap measured while reading
the stream (Content-Length alone is insufficient). Reject arrays, null, extra
keys, invalid enums and noncanonical UUIDs before mutation. UUIDs are canonical
hyphenated hexadecimal, case-normalized; nil UUIDs are invalid. IDs generated by
clients use Expo Crypto `randomUUID`, not a provider polyfill's random fallback.
No client actor, recipient, room, provider identity, binding or clock fields.
Validate responses too; unknown status/revision or malformed capability data is
an explicit protocol error, never permission to join.

Public JSON uses camelCase; Postgres columns/RPC arguments use snake_case.
Times are RFC 3339 UTC strings; missing times/actors/reasons are JSON null.
SQL bigint revisions serialize as decimal **strings**, avoiding JavaScript's
integer precision limit; compare with BigInt after decimal validation. They
start at 1 and increase on authoritative changes. Participant revisions are
independent of call revisions. Never serialize bigint directly with JSON.stringify.

New shared types to implement in later phases:

- `CallMediaType`: `voice | video`.
- `CallStatus`: `ringing | accepted | in_progress | declined | cancelled |
  missed | ended | failed`. Last five are terminal.
- `CallEndReason`: `declined | cancelled | no_answer | busy | hangup |
  connection_timeout | media_disconnected | permission_denied | provider_error |
  access_lost | account_restricted | max_duration | feature_disabled`.
  Role/status/reason combinations follow the transition table below.
- `CallState`: `callId, chatId, callerId, calleeId, mediaType, status,
  createdAt, ringExpiresAt, acceptedAt, connectExpiresAt, connectedAt,
  endedAt, endedBy, endReason, revision`. No request IDs or internal data.
- `CallCapabilities`: booleans `canAnswer, canCancel, canJoin, canEnd,
  belongsToThisSession`. Snapshot derives these for the verified actor/runtime.
  `canDecline` need not be a field: only an eligible, unexpired incoming ringing
  invitation presents decline. Action-time checks remain authoritative.
- `CallParticipant`: `callId, userId, role` (`caller | callee`),
  `connected` (boolean), `connectionGeneration` (decimal revision string),
  nullable `joinedAt, leftAt`, and `revision` (decimal string).
  No SDK identity, device binding, SID or user-supplied connection claims.

### User endpoints

All require the active user's JWT, verified server-side through Supabase Auth.
Never decode an unverified JWT and trust its subject. The Edge service-role
client forwards only the **verified** actor to SQL. Retain platform verification
where supported by the target's JWT signing mode; verify that mode at deployment
instead of copying `verify_jwt=false` from existing webhook functions.

| Endpoint | Exact allowed request keys | Successful body |
| --- | --- | --- |
| `call-action` create | `action:'create', chatId, mediaType, requestId, clientSessionId` | `CallSnapshot` below |
| `call-action` lifecycle | `action:'accept'|'decline'|'cancel'|'end', callId, requestId, clientSessionId` | `CallSnapshot` |
| `call-action` snapshot | `action:'snapshot', clientSessionId`, optional `callId` | `CallSnapshot` |
| `call-token` | `callId, clientSessionId` | `{serverUrl, participantToken, expiresAt, callId, revision, serverTime}` |

`CallSnapshot = {call: CallState|null, participants: CallParticipant[],
capabilities: CallCapabilities, availability: {callingEnabled:boolean},
serverTime:string, cleanupState:'not_required'|'pending'|'confirmed'|'failed'}`.
No-call snapshots return empty participants, all-false capabilities and
`not_required`. A specified inaccessible call returns 404, not a null snapshot.
An unspecified snapshot finds the actor's one live reservation/incoming call;
terminal history is fetched separately. Use server time to dismiss expired
ringing even before the sweep runs. Return HTTP 200 for successful/idempotent
actions; terminal state with pending cleanup is still a successful SQL transition,
never a claim that remote media stopped. Mark responses `Cache-Control: no-store`.

Errors: `{code, message, retryable, retryAfterSeconds?:number, call?:CallState}`.
`message` is safe shared copy, never SDK/error objects. Include `call` only for a
recorded accessible busy attempt; all other errors omit it. This lets the caller
record busy history without revealing another call's participants or existence.

| HTTP | Code | Retry policy |
| --- | --- | --- |
| 400 | `CALL_INVALID_REQUEST` | Fix input; no automatic retry. |
| 401 | `CALL_UNAUTHENTICATED` | Refresh/sign in through existing auth; no media. |
| 403 | `CALL_NOT_ALLOWED` | Eligible chat/actor restriction; no retry. |
| 404 | `CALL_NOT_FOUND` | Inaccessible/nonexistent specified call; same envelope. |
| 409 | `CALL_BUSY`, `CALL_EXPIRED`, `CALL_ALREADY_HANDLED`, `CALL_REQUEST_CONFLICT` | Snapshot/reconcile, no new attempt ID automatically. |
| 503 | `CALL_PROVIDER_UNAVAILABLE` | One bounded transport retry while still live. |
| 503 | `CALL_FEATURE_DISABLED` | `retryable:false`; preserve cleanup/history. |
| 429 | `CALL_RATE_LIMITED` | `Retry-After` seconds and matching positive `retryAfterSeconds`; respect deadlines. |
| local only | `CALL_PERMISSION_REQUIRED`, `CALL_OFFLINE`, `CALL_PROTOCOL_ERROR`, `CALL_RUNTIME_UNAVAILABLE` | User action/error UI; never a client claim to SQL. |

Client action/token timeout: 10 seconds. One retry for transient transport/5xx
only, with the original lifecycle request ID. Token retries use the same
call/runtime, reauthorize and may mint a new token; they never create another
room/connection. Never retry 503 feature-disabled or 4xx as transient failures.
Snapshot capabilities do not let a new runtime end/take over an old binding.

## Database contracts for Phase 1

All new operational tables are in `private`, excluded from Realtime and normal
API schemas. Only `public.calls` and `public.call_participants` expose safe rows.
Create participant-only SELECT RLS additionally requiring current membership.
Direct client INSERT/UPDATE/DELETE and lifecycle RPC execution are denied.
Membership in a chat does not grant access to another historical caller/callee pair.

| New relation | Required column contract / constraints |
| --- | --- |
| `public.calls` | UUID `call_id` PK, `chat_id` FK to chats.chat_id, `caller_id`, `callee_id` FKs to Auth users; text `media_type`, `status`; timestamptz `created_at`, `ring_expires_at`, nullable `accepted_at`, `connect_expires_at`, `connected_at`, `ended_at`; nullable UUID `ended_by`; nullable text `end_reason`; bigint `revision`; UUID `request_id`; UNIQUE(caller_id,request_id), caller≠callee. Auth/chat FKs cascade. |
| `public.call_participants` | PK(call_id,user_id); call FK cascades; role, connected, bigint connection_generation/revision, nullable joined_at/left_at. Exactly caller and callee rows inserted transactionally, including a recorded busy attempt. |
| `private.call_user_reservations` | user_id PK, call_id cascading FK, due_at timestamptz. Stable user UUID lock order. Unique rows reserve both participants across chats/devices. |
| `private.call_rooms` | call_id cascading PK/FK; UNIQUE opaque room_name; nullable room_sid; bigint epoch, room_generation; caller_session_id, nullable callee_session_id; opaque caller_identity/callee_identity; readiness enum `unprovisioned|provisioning|ready`; operation UUID and lease deadline; latest finalized token nbf/exp per identity in Unix seconds; next_reconcile_at; nullable disconnect deadlines. No tokens. |
| `private.call_admissions` | admission_id UUID PK; call_id cascading FK; actor_id, client_session_id; epoch; issued_at/lease_expires_at; nullable finalized_nbf/finalized_exp (bigint seconds). A separately identifiable lease per request prevents parallel token issuance from overwriting another lease. Expired/terminal leases cannot finalize. |
| `private.call_action_requests` | PK(actor_id,request_id); action; normalized call/chat/media input identity; nullable result_call_id. Stores deduplication identity, never tokens/capabilities. A reused ID with different inputs is conflict. Remove with its call after deletion; deleted/inaccessible inputs still fail before any replay. Persist create failures only when a valid busy attempt exists. |
| `private.call_jobs` | job_id UUID PK, unique dedupe_key, nullable diagnostic call_id **without FK**, kind `cleanup` initially; immutable room_name, identities, room/operation generation and termination epoch; max finalized nbf/expiry; outstanding_operation_until; attempts, next_attempt_at, lease_id/lease_expires_at; state `pending|claimed|confirmed|failed`; safe error code. Survives cascades. Retain unresolved tombstones. |
| `private.call_webhook_events` | provider_event_id text PK, event_time, room_sid, identity/generation needed for correlation, state `pending|processed|failed`, safe error code. No raw payload/signature/token. Bound body processing before persistence. |
| `private.call_settings` | singleton boolean PK constrained true; calling_enabled=false, call_push_enabled=false, native_background_enabled=false; UUID[] pilot_user_ids default empty; ring_seconds=30, connect_seconds=30, disconnect_grace_seconds=20, maximum_duration_seconds=1800, reconcile_seconds=10; create_limit=5/window=60s, token_limit=10/window=60s; missed_streak_limit=3/window=600s/cooldown=60s. Positive/check-bounded values. |
| `private.call_rate_limits` | composite subject/scope/window-event identity; event time, request ID dedupe, pair missed streak/cooldown state. Index subject/time. Service-only, transactional sliding-window limits across devices; finite obsolete-window pruning by SQL worker. |

Nullable lifecycle invariants: terminal iff ended_at and end_reason are nonnull;
ended_by is null for worker/busy/policy failures, otherwise one participant.
accepted/connect deadline appear together after acceptance and survive terminal
history; connected_at only after a verified simultaneous connection; ended_at
cannot precede created/accepted/connected times. Busy has no acceptance/media
timestamps. `ring_expires_at = created_at + ring window`; the persisted connection
deadline uses the settings captured on accept. Existing calls keep their deadlines
when settings change. Increment revisions on changed rows only; duplicate replay
must not regress timestamps or inflate history.

Indexes: participants(user_id,call_id); calls(chat_id,created_at DESC,call_id DESC);
due reservations/rooms and runnable jobs; rate-window subject/event time.
Only safe public tables join `supabase_realtime`. No private schema publication.

### Service-only RPC signatures (new, not existing)

Use `public` for the following PostgREST-callable functions but REVOKE ALL from
PUBLIC/anon/authenticated; GRANT EXECUTE only to service_role. Private helpers
fully qualify names, pin `search_path=''` and explicitly authorize actor/action.
SQL parameters cannot stand in for verified Edge authentication.

| Function | Named arguments / result |
| --- | --- |
| `call_create` | `p_actor_id uuid, p_chat_id uuid, p_media_type text, p_request_id uuid, p_client_session_id uuid` → safe JSON transition result; derive callee from locked exactly-two distinct members. |
| `call_transition` | `p_actor_id uuid, p_call_id uuid, p_action text, p_request_id uuid, p_client_session_id uuid` → safe JSON result; user actions only. |
| `call_snapshot` | `p_actor_id uuid, p_client_session_id uuid, p_call_id uuid default null` → CallSnapshot projection, including flags and ownership. |
| `call_prepare_admission` | `p_actor_id uuid, p_call_id uuid, p_client_session_id uuid` → **private Edge-only** admission_id, epoch, lease_expires_at, room readiness/name, opaque identity, allowed media, current revision. Lease 10 seconds; no token while provisioning. |
| `call_finalize_admission` | `p_actor_id uuid, p_call_id uuid, p_client_session_id uuid, p_admission_id uuid, p_epoch bigint, p_token_nbf bigint, p_token_exp bigint` → `{authorized, revision, server_time}`. Recheck all permissions/deadlines and update greatest finalized metadata only when authorized. |
| `call_reconcile` | `p_call_id uuid, p_job_lease_id uuid, p_epoch bigint, p_room_generation bigint, p_observation jsonb` → worker result. Only an internally claimed lease can apply verified provider observations, never a user endpoint. Validate observation schema. |

Lifecycle/snapshot RPCs return the camelCase `CallSnapshot` directly on success;
the Edge does not invent a second state serializer. SQL business failures use
SQLSTATE `P0001` with MESSAGE equal to one of the stable CALL_* codes above,
without private DETAIL payloads. The Edge maps these to the declared HTTP/error
envelope. Unexpected SQL errors become a safe provider-unavailable response and
metadata-only diagnostics, never a raw database error. The valid busy attempt
returns a snapshot whose call is failed/busy; Edge returns 409/CALL_BUSY with its
safe call projection. This outcome is persisted/deduplicated before responding.

`call_prepare_admission`'s exact private JSON result uses snake_case:
`{admission_id:uuid, epoch:decimalString, lease_expires_at:utcString,
room_name:string, room_sid:string|null, room_generation:decimalString,
participant_identity:string, media_type:CallMediaType,
readiness:'unprovisioned'|'provisioning'|'ready',
operation_id:uuid|null, operation_lease_expires_at:utcString|null,
revision:decimalString, server_time:utcString}`. Never return it to a client.
If not ready, the fenced provisioning operation must settle first; acquire a
fresh admission lease afterward and leave the earlier lease unused/expired.
An unready result never authorizes token signing or a client connection.
`call_finalize_admission` returns an authorized boolean plus revision/server_time
only when still eligible; false returns null revision and no usable token.

Worker observation JSON is a closed discriminated union, all snake_case:
`{observed_at:utcString, result:'unknown', error_code:'timeout'|'unavailable'}`;
`{observed_at:utcString, result:'missing'}`; or
`{observed_at:utcString, result:'present', room_sid:string,
participants:[{identity:string, participant_sid:string}]}`. At most two expected
identities may appear; unexpected participants trigger removal/alert rather than
acceptance. Validate size, uniqueness and room-generation match. Store the last
observed participant SID per identity privately in call_rooms and increment its
connection generation when that SID changes; publish only the resulting safe
generation. Stale webhook participant SIDs cannot replace a newer observation.
Worker result is `{applied:boolean, call_id:uuid, revision:decimalString|null,
next_reconcile_at:utcString|null, cleanup_state:'not_required'|'pending'|'confirmed'|'failed'}`.
A stale lease/epoch returns applied=false without mutation. Job claims/provision
finalization are private implementation helpers, not additional user contracts.

Additional private worker helpers claim due batches (`FOR UPDATE SKIP LOCKED`),
finalize provisioning against operation/epoch, and enqueue deletion-safe cleanup.
Their exact implementation is private to Phase 1; they do not introduce another
client API. Provider observations contain observation time, matching room SID,
expected participant presence/generation and classified provider result. A
timeout is `unknown`, never proof of absence. Don't hold SQL locks during HTTP.

Recheck both users' Auth ban/password-change state transactionally on
create/accept/admission and in worker reconciliation. The target's actual
`auth.users` columns must be inspected before implementing the helper; public
app_metadata from the Auth admin API is a verified logical contract, not proof
of a particular SQL column on the uninspected target. Bound participants with
a valid JWT retain end/cancel rights after restriction/access loss. Ordinary
specified snapshots/history still return 404 after membership loss. An explicit
end/cancel from the already-bound participant is the narrow cleanup exception:
it may return that participant's own terminal snapshot, without requiring current
membership or active-account status. No new admission is allowed. Invalid JWTs
get no action. Ordinary unbound sessions cannot end.

### Transitions and ownership

| From | Action / authority | Result / reason |
| --- | --- | --- |
| none | eligible create, both reservations succeed | ringing / null; bind caller runtime immediately |
| none | eligible create, either reserved | failed / busy; separate history, leave existing reservation untouched |
| ringing | callee accept strictly before ring deadline | accepted / null; bind first winning callee runtime; connect deadline +30s |
| ringing | callee deliberate decline | declined / declined |
| ringing | bound caller cancel | cancelled / cancelled |
| ringing | worker/server deadline | missed / no_answer |
| accepted | worker verifies both expected current-room identities connected | in_progress / null; set first connected_at |
| accepted | bound participant end | ended / hangup; zero duration |
| accepted | connection timeout, unrecoverable permission/provider failure or policy termination | failed / connection_timeout, permission_denied, provider_error, access_lost, account_restricted or feature_disabled |
| in_progress | bound participant end or policy cap/access/restriction/drain | ended / hangup, max_duration, access_lost, account_restricted or feature_disabled |
| in_progress | confirmed unrecovered media loss/provider failure | failed / media_disconnected or provider_error |

Terminal replay returns state without reopening it. Accept after another callee
runtime wins returns conflict and a snapshot with belongsToThisSession=false.
Unbound callee local dismissal on logout/background is **not decline**. Local
blocked-chat auto-decline is a deliberate bounded callee action while ringing.
Use row locks/deadline checks for races, never a client-provided revision as
authorization. History page size 30, ordered `(created_at DESC,call_id DESC)`,
strict tuple cursor, actor still in chat and recorded pair, no offset paging.

## Admission, provisioning and cleanup

1. Create/accept do not mint tokens. After accept, one fenced operation provisions
   the unique opaque room with maxParticipants=2. No SDK connection while ringing.
2. Prepare locks/rechecks actor, both users, membership, selected session, flags,
   state/deadlines/duration/rate and epoch; return a unique 10-second lease.
3. Sign through `npm:livekit-server-sdk@2.19.3` with explicit `ttl:300` and opaque
   identity. Grant roomJoin, subscribe and required microphone/camera sources;
   explicitly deny data/metadata/admin/list/create/record. No screen source or PII.
4. Finalize rereads state/lease/epoch/permissions and records nbf/exp from the
   actual signed JWT, never estimates. Only then return the token; keep it in
   client memory. Failed finalize means discard it and return no credential.
5. Every terminal transaction increments epoch, invalidates leases, releases both
   reservations and enqueues cleanup atomically. BEFORE DELETE snapshots immutable
   room/identities/outstanding operations into a job with no cascading FK.
6. A late create completion cannot mark a terminal/deleted call ready. Reopen
   cleanup by immutable room/operation identity even if an earlier delete saw
   no room. A timed-out create is an uncertain operation, not a cancelled one.
7. Remove both identities concurrently with `revokeTokenTs: bigint` in **seconds**,
   then delete room. Explicit cutoff must be within provider current time ±60s
   and strictly greater than every finalized nbf; equal-second issuance requires
   the next second cutoff. Retry with a current cutoff, not stale termination time.
   If those inequalities cannot both hold, record unconfirmed cleanup and escalate;
   never return a false security pass. Refresh/clock/window behavior needs V2.
8. Server SDK options **`{requestTimeout:5, failover:false}`** disable its otherwise
   enabled regional retry mechanism. Removal+delete shares the handler's overall
   five-second provider budget; assign each stage only the time remaining.
   An outer Promise.race alone does not cancel requests: retain uncertain side
   effects in durable jobs. Interactive SQL terminal state can return pending.
9. Jobs use fenced claims and backoff 2/5/15/60 seconds; after five unsuccessful
   attempts mark failed/alert, retain metadata for controlled recovery. Retry
   workers cannot claim provider completion from room-not-found before outstanding
   create operations settle. No raw credentials in jobs/errors/logs.
10. Ten-second SQL sweep checks due deadlines/jobs only. A lost webhook must not
    strand live calls. Provider absence starts 20-second grace; unknown observation
    retains reconciling state. SQL independently ends at connected_at+1800s during
    provider outage, releases reservations and denies tokens while cleanup waits.

Webhook: `new WebhookReceiver(key,secret).receive(rawBody,authorization)` with
default authentication enabled. Validate event ID, recognized event type and
current room SID/generation, dedupe before applying, reconcile ambiguous order.
Late joins never reopen terminal state. Scheduler endpoint uses a separate
server credential and cannot be invoked with an ordinary user JWT.

## Native import, permissions and audio contracts

The candidate versions and evidence are in [compatibility.md](compatibility.md).
Phase 3 must gate **before evaluating** either native SDK: Android/iOS platform,
not Expo Go, and presence/method shape of RN `NativeModules.WebRTCModule` and
`NativeModules.LivekitReactNativeModule`. These are RN modules, not Expo modules;
do not pass their names to requireOptionalNativeModule. SDK entrypoints evaluate
native events immediately. Required method checks include WebRTCModule
`getUserMedia`/`peerConnectionInit` and LivekitReactNativeModule
`configureAudio`/`startAudioSession`/`stopAudioSession`/`getAudioOutputs`/
`selectAudioOutput`, confirmed in the pinned JS/native sources. Shape checks
are a conservative missing-native guard, not a replacement for artifact identity.
Cache supported bootstrap and call registerGlobals
once per runtime. Disabled/missing-native/web paths never evaluate those imports.

Use RN 0.86 PermissionsAndroid check/request for RECORD_AUDIO and CAMERA;
request BLUETOOTH_CONNECT on API 31+ only in the route flow when needed. Mic denial
prevents create/accept; camera denial permits explicit camera-off video answer.
Denied vs never_ask_again routes to retry vs Settings; don't auto-prompt on render.
Stop any capture started during a failed/cancelled prepare. Permission blur is
not confirmed background.

After existing recorder/player ownership releases, configure communication audio,
preferred output order bluetooth/headset/earpiece/speaker for voice and
bluetooth/headset/speaker/earpiece for video, then startAudioSession before connect.
getAudioOutputs returns available choices; selectAudioOutput resolves void and
does **not** confirm physical/current routing. The candidate has no public
current-route getter/event. Phase 3 may expose available-output requests with
honest pending/unknown state, but cannot mark CALL-07's actual-route acceptance
passed until direct ADB/audio evidence or a supported state bridge resolves it.
Do not invent a route getter or infer success from the icon. A needed native
bridge is a recorded gate, not permission to hand-edit generated Android code.

Use LocalParticipant setMicrophoneEnabled; SDK-owned camera setCameraEnabled
false stops capture in LocalVideoTrack.mute. Camera restartTrack({facingMode})
is the public switching candidate, guarded by enumerated available cameras.
Avoid the WebRTC track's private `_switchCamera`. Stop tracks, disconnect room,
remove listeners/timers and stopAudioSession idempotently on each exit; then
restore Expo audio ownership. All async completions carry account/runtime generation.
