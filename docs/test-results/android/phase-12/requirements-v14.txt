| D-75 | Chat media lives in two private buckets by size class: chat-media-small (photos and voice notes; 10 MB; the image and audio types of 5.5) and chat-media-large (videos and files; 50 MB; every type of 5.5). | D-90 | Message integrity is enforced by triggers. messages.attachment_count (0 to 10) is written at insert and cannot change. A message whose kind is text and whose attachment_count is 0 must not have blank content. A message_media insert is rejected once the message has attachment_count rows. reply_to must name a message in the same chat. content is at most 4096 characters, or in a secret chat at most 22,000 characters of base64 (^[A-Za-z0-9+/=]*$), so plaintext cannot be stored there by mistake. An update is rejected once expires_at has passed. On message_media the trigger sets storage_path to {chat_id}/{media_id} and requires an object at that path in the bucket of the media_type, whose owner_id is the caller and whose declared type matches the media_type (photo image/*, voice audio/*, video video/*, file any type of 5.5). Clients show one placeholder for each attachment that has no row yet. Assumption: Storage compares allowed_mime_types with the declared Content-Type, not the file bytes; accepted, because every reader is a chat member and the apps never execute a file.
